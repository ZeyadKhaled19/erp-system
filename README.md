# نظام الحسابات والمخازن (ERP)

نظام ERP عربي للحسابات والمخازن والمبيعات والمشتريات والخزينة. يعمل على المتصفح، ويُثبّت كتطبيق (PWA) على ويندوز والهواتف، ويعمل **دون إنترنت** مع مزامنة تلقائية عند عودة الاتصال. واجهته بأسلوب iPadOS بالوضع الفاتح.

> الحالة: **المرحلة الأولى**. ما اكتمل وما لم يكتمل مكتوب بالتفصيل في [docs/STATUS.md](docs/STATUS.md).

---

## المكونات والتقنيات

| الجزء | التقنية | سبب الاختيار |
|---|---|---|
| الواجهة | React 19 + TypeScript + Vite | قاعدة كود واحدة للويب وويندوز والموبايل |
| التثبيت والعمل دون اتصال | PWA (vite-plugin-pwa / Workbox) | يُثبّت من المتصفح على Windows وAndroid وiOS، ويحفظ ملفات الواجهة والخطوط محليًا |
| قاعدة البيانات المحلية | IndexedDB عبر Dexie | تخزين دائم على الجهاز يبقى بعد إغلاق البرنامج وإعادة التشغيل |
| الخادم | Node.js + Fastify + TypeScript | خفيف وسريع، ويتشارك الكود مع الواجهة (حسابات الفواتير والصلاحيات) |
| قاعدة البيانات المركزية | PostgreSQL | معاملات (Transactions) موثوقة للحسابات |
| PostgreSQL مدمج للتشغيل المحلي | PGlite | يعمل دون تثبيت أي شيء؛ ونفس الكود يعمل على PostgreSQL حقيقي في الإنتاج |
| التحقق من البيانات | Zod | نفس قواعد التحقق في الخادم والواجهة |

البنية:

```
packages/shared   قواعد مشتركة: الحساب المالي بالأعداد الصحيحة، حساب الفواتير، الصلاحيات، تعريف العمليات
apps/server       الخادم: قاعدة البيانات، الترحيل المحاسبي، المزامنة، التقارير، النسخ الاحتياطي
apps/web          الواجهة: PWA، قاعدة محلية، طابور المزامنة، الشاشات
scripts           اختبار قبول حقيقي للعمل دون اتصال على متصفح Edge/Chrome
docs              التصميم والحالة والقرارات المنتظرة
```

تفاصيل التصميم المحاسبي والمزامنة موجودة في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## التشغيل المحلي

المتطلبات: Node.js 20 أو أحدث. Docker اختياري.

```bash
npm install
```

```bash
npm run build
```

```bash
npm start
```

بعدها افتح `http://localhost:4000`.

- **الدخول الأول:** المستخدم `admin` وكلمة المرور `admin123`. **غيّرها فورًا** من شاشة الإعدادات.
- **البيانات:** تُحفظ في `data/pg` (PGlite)، والنسخ الاحتياطية في `backups/`.

### التشغيل التلقائي مع Windows

حتى لا يتوقف النظام عند إغلاق الكمبيوتر أو إعادة تشغيله، ثبّت مهمة التشغيل التلقائي مرة واحدة:

```bash
powershell -ExecutionPolicy Bypass -File scripts/windows/install-autostart.ps1
```

- يعمل الخادم في الخلفية تلقائيًا كل مرة تسجّل فيها الدخول إلى Windows، ويُعاد تشغيله وحده إذا توقف.
- السجل في `logs/server.log`.
- الإزالة: نفس الأمر مع `-Remove`.
- اضبط `JWT_SECRET` بقيمة عشوائية في `.env` قبل الاستخدام الفعلي.

### وضع التطوير

```bash
npm run dev
```

بيشغّل الخادم على المنفذ 4000 والواجهة على `http://localhost:5173`، ومعاه إعادة تحميل تلقائية مع كل تعديل.

### الإعدادات

انسخ `.env.example` إلى `.env` وعدّل القيم. أهمها:

| المتغير | الوصف |
|---|---|
| `JWT_SECRET` | سر توقيع جلسات الدخول. **لازم** يبقى قيمة عشوائية طويلة في الاستخدام الفعلي |
| `DATABASE_URL` | لو فاضي هيُستخدم PGlite. للإنتاج حط رابط PostgreSQL |
| `ADMIN_INITIAL_PASSWORD` | كلمة مرور المدير عند إنشاء قاعدة جديدة |
| `PORT` / `BACKUP_DIR` / `PGLITE_DIR` | المنفذ ومجلد النسخ الاحتياطية ومجلد بيانات PGlite |

## التثبيت على الأجهزة (PWA)

- **ويندوز (Edge أو Chrome):** افتح عنوان الخادم، ومن شريط العنوان اضغط أيقونة «تثبيت التطبيق».
- **أندرويد (Chrome):** من القائمة اختر «إضافة إلى الشاشة الرئيسية» أو «تثبيت».
- **آيفون وآيباد (Safari):** زر المشاركة، ثم «إضافة إلى الشاشة الرئيسية».

> التثبيت والعمل دون اتصال على أجهزة غير الجهاز نفسه يحتاجان اتصالًا آمنًا (HTTPS)، لأن المتصفحات لا تسمح بـ Service Worker على HTTP إلا على `localhost`. على الشبكة المحلية استخدم شهادة HTTPS، وعلى الإنترنت استخدم نطاقًا بشهادة (مثلًا عبر Caddy أو Nginx). شوف قسم النشر.

**أول تسجيل دخول على أي جهاز يحتاج اتصالًا.** بعدها يشتغل البرنامج من غير إنترنت.

## العمل دون اتصال والمزامنة

- كل ما يُسجَّل يُحفظ فورًا على الجهاز، ويُضاف لطابور عمليات بالترتيب.
- مؤشر أعلى الشاشة يوضح حالة الاتصال وعدد العمليات المنتظرة. اضغط عليه لفتح **مركز المزامنة**.
- المستند المسجل من غير نت يظهر برقم مؤقت (`TMP-…`) وحالة «بانتظار المزامنة». الرقم الرسمي (`S-00001`) يصدر من الخادم عند قبوله.
- لو اتقطع الاتصال أثناء الإرسال، العملية بتتبعت تاني بنفس المعرّف، والخادم مش بيكررها أبدًا.
- **تعديل نفس السجل من جهازين:** الخادم لا يكتب فوق التعديل الأقدم بصمت. بيسجّل «تعارض» يحله مستخدم عنده الصلاحية.
- **البيع بكمية أكبر من الرصيد مركزيًا** (مثلًا جهازين باعوا آخر قطعة وهما offline): الفاتورة تُحفظ بحالة «يحتاج مراجعة» ولا تُرحّل. المستخدم المخول يختار إما يرحّلها رغم العجز، أو يرجّعها مسودة، أو يلغيها.

## النسخ الاحتياطي والاستعادة

- **تلقائي:** نسخة قبل أي تحديث لهيكل قاعدة البيانات (migration)، ونسخة أمان قبل أي استعادة.
- **من البرنامج:** شاشة «النسخ الاحتياطي». فيها إنشاء نسخة، وتحميلها، واستعادتها.
- **من سطر الأوامر:** لإنشاء نسخة:

  ```bash
  npm run backup
  ```

  ولاستعادة نسخة:

  ```bash
  npm run restore -- backups/erp-backup-....json
  ```

النسخة ملف JSON يحتوي كل الجداول، ويصلح لـ PGlite ولـ PostgreSQL. بعد الاستعادة، كل الأجهزة بتعيد تحميل البيانات تلقائيًا، والعمليات اللي لسه مترفعتش على الأجهزة بتفضل محفوظة.

> انسخ ملفات `backups/` دوريًا لمكان تاني (فلاشة أو تخزين سحابي).

## النشر للإنتاج

1. شغّل PostgreSQL. المشروع فيه `docker-compose.yml` جاهز:

   ```bash
   docker compose up -d db
   ```

2. اضبط `.env`:
   - `DATABASE_URL=postgres://erp:<password>@localhost:5432/erp`
   - `JWT_SECRET` بقيمة عشوائية طويلة
   - كلمة مرور قوية لـ PostgreSQL في `POSTGRES_PASSWORD`

3. ابنِ الواجهة وشغّل الخادم:

   ```bash
   npm ci
   ```

   ```bash
   npm run build
   ```

   ```bash
   npm start
   ```

   لو عاوز الخادم يشتغل كخدمة دائمة، استخدم pm2 أو خدمة ويندوز.

4. ضع الخادم خلف HTTPS، مثلًا Caddy: `caddy reverse-proxy --from erp.example.com --to localhost:4000`.

5. الـ migrations بتتطبق تلقائيًا عند التشغيل، وقبلها بتتاخد نسخة احتياطية.

## الاختبارات

اختبارات الوحدات والتكامل:

```bash
npm test
```

نفس اختبارات الخادم على PostgreSQL حقيقي (بعد تشغيل `docker compose up -d db` وإنشاء قاعدة `erp_test`):

```bash
TEST_DATABASE_URL=postgres://erp:erp-dev-password@localhost:5432/erp_test npm test -w @erp/server
```

اختبار القبول للعمل من غير نت على Edge أو Chrome المثبت (بعد `npm run build`):

```bash
node scripts/e2e-offline.mjs
```
